# Cave Flight (FluppyBat)

Браузерная аркада: летучая мышь летит сквозь процедурные пещеры. Соло и сетевые лобби до 16 игроков.

## 1. Стек и структура

- **Backend** — ASP.NET Core (.NET 10): статика из `wwwroot`, SignalR-хаб `/gameHub`.
- **Frontend** — HTML5 Canvas, JavaScript (ES6+), цикл 60 FPS, физика и коллизии на клиенте.
- **UI** — Tailwind CSS и Google Fonts через CDN (нужен интернет).
- **Сеть** — общий мир: сервер выдаёт seed, клиенты строят одинаковые препятствия.

```
SQFLUPPY2/
├── Models/ Services/ Hubs/   # DTO, LobbyRegistry + PBKDF2-хеши, GameHub
├── App_Data/                 # lobbies.json (создаётся сам)
├── wwwroot/
│   ├── images/               # bg0-9.jpg, bat_up/down.png, rock0-9.png
│   └── index.html            # JS, рендеринг, физика, полигоны
├── Program.cs, appsettings.json
SQFLUPPY2.Tests/              # xUnit-тесты реестра лобби
```

## 2. Как запустить локально

1. Установите **.NET SDK 10.0+** и проверьте: `dotnet --version`.
2. Запустите сервер:

   ```powershell
   cd C:\Users\Klim\Desktop\FluppyBat-main\SQFLUPPY2
   dotnet run
   ```

   Порт `http://localhost:5079` берётся из `Properties/launchSettings.json`; явно —
   `dotnet run --urls http://localhost:5079`.
3. Откройте <http://localhost:5079>. Первая загрузка дольше: Tailwind и шрифты идут с CDN
   (без интернета страница откроется без стилей, но игра работает).
4. Остановить — `Ctrl+C` в терминале.

**С друзьями по локальной сети:** `dotnet run --urls http://0.0.0.0:5079`, разрешить порт в
файрволе, дать друзьям адрес машины (`http://192.168.1.10:5079`). Для игры через интернет нужен
внешний адрес или туннель — игра сама его не настраивает.

**Тесты:** `cd SQFLUPPY2.Tests; dotnet test`.

## 3. Управление

- **Пробел / ЛКМ** — импульс вверх. **H** — подсветка коллизионных полигонов.
- Скалы идут парами (верхние сталактиты от `y = 0`, нижние сталагмиты от земли), проход смещён
  случайно относительно центра.
- Гибель только от скал и земли; удар о потолок не убивает — птица упирается и теряет скорость.
- Фон прокручивается постоянно, биом (10 пресетов) меняется каждые 20 очков.

## 4. Сетевой режим

**Вход** — ровно три способа, других нет:

1. **Создать лобби**: название, необязательный пароль (от 4 символов), никнейм → вы хост.
2. **По ссылке**: `/?lobby=ABC123` — шестисимвольный код комнаты, регистр не важен.
3. **По названию**: название (регистр не важен) и пароль, если задан.

**Правила:**

- Никнейм обязателен и уникален среди подключённых; вместимость 16 (`lobby_full` при заполнении).
- Хост запускает раунд (можно в одиночку), меняет сложность (легко/нормально/сложно) и биом,
  передаёт роль хоста; при выходе роль переходит следующему подключённому.
- Позиции передаются в нормализованных координатах (0..1), не зависят от размера окна.
- Погибший — зритель. Раунд кончается, когда погибли все подключённые; дальше таблица результатов
  (за раунд и накопительно) и возврат в лобби. К идущему раунду не подключиться.
- После обрыва связи место держится 60 с. Состояние в памяти + `App_Data/lobbies.json`, пароли —
  только PBKDF2-хеши.

## 5. Физика и коллизии

### 5.1. Константы (как в оригинальном Flappy Bird)

Оригинал работает в поле 288×400 px: гравитация 0.25 px/кадр², импульс −4.6 px/кадр, предел
падения 10 px/кадр. Чтобы всё не зависело от размера окна, значения хранятся в долях высоты поля
(деление на 400) и умножаются на `playH()`:

```js
const PHYS = {
    gravity: 0.25 / 400, jump: -4.6 / 400, maxFall: 10 / 400,
    rotationUp: -25, rotationDown: 90, rotationLerp: 0.18
};
```

Прыжок ≈ 42 px на поле 400 px (4.6² / (2·0.25)), до верхней точки ≈ 18 кадров; наклон
интерполируется с поправкой на длительность кадра, поэтому при просадке FPS анимация не ускоряется.
Скорость и просвет скал — в `DIFFICULTIES`.

### 5.2. Хитбокс и полигоны

**Хитбокс** не привязан к размеру PNG: ширина 10 %, высота 7.7 % от высоты поля — спрайты можно
менять на любые, место на экране не изменится.

**Автопостроение.** Фон спрайтов непрозрачно-белый, поэтому силуэт ищется по отличию от белого с
заливкой от краёв (светлые детали внутри модели сохраняются). Контур упрощается (Дуглас–Пекер),
ограничивается по числу вершин и переводится в выпуклую оболочку для SAT. Строится один раз при
загрузке и кэшируется; настройки — `POLYGON_OPTIONS` (`whiteThreshold` 236, `alphaMin`, `maxRows`,
`maxVertices`, `tolerance`). Птица сталкивается повёрнутым полигоном, поэтому задевание скалы
«кончиком крыла» засчитывается.

### 5.3. Как заменить модельку

1. Положите PNG с белым фоном в `wwwroot/images`.
2. Если имя совпадает с существующим (`bat_up.png`, `bat_down.png`, `rock0.png`…`rock9.png`) —
   больше ничего не нужно, полигон пересчитается при загрузке.
3. Новый файл зарегистрируйте в списках: `batUpImg`/`batDownImg` — птица, `topRockImages` —
   сталактиты, `bottomRockImages` — сталагмиты.
4. Пропорции любые: спрайт вписывается в прямоугольник препятствия, белые поля обрезаются.

Если авто-контур неудачный, задайте форму вручную в `POLYGON_OVERRIDES`: ключ — путь к картинке,
значение — точки в долях (0..1) от видимой области модели. Порядок не важен, форма может быть
невыпуклой — для столкновений берётся выпуклая оболочка.

```js
const POLYGON_OVERRIDES = {
    'images/rock0.png': [
        { x: 0.5, y: 0 }, { x: 0.95, y: 0.75 }, { x: 0.55, y: 1 }, { x: 0.05, y: 0.75 }
    ]
};
```

**Отладка.** **H** в игре: полигоны скал — розовые, контур птицы — циановый, её оболочка — жёлтая;
в HUD плашка «Полигоны включены (H)» и номер кадра птицы. Повторное нажатие выключает подсветку,
она же сбрасывается при завершении раунда и выходе в лобби.

### 5.4. Прямой полёт в начале раунда

До первого Пробела/клика птица держит высоту `playH() / 2`, фон прокручивается, но препятствия не
двигаются и не появляются, а `game.travelled` заморожен — игрок начинает с чистого поля. Первое
нажатие завершает фазу и сразу даёт импульс, поэтому птица не падает камнем вниз.

В этой фазе птица статична: один кадр (`bat_up`), наклон ноль. Переключать `bat_up`/`bat_down`
нельзя — у спрайтов разные пропорции, и их смена в одном прямоугольнике визуально «дёргала» птицу.
Кадр по вертикальной скорости выбирается после старта (`flappingUp()` → `birdImage()`).

`READY_TIMEOUT_MS = 10000` ограничивает ожидание в сети: раунд кончается только когда погибли все,
поэтому один отвлёкшийся игрок заморозил бы остальных (в свёрнутой вкладке `requestAnimationFrame`
не тикает, поэтому автостарт продублирован через `setTimeout`). В соло ожидание бессрочное. В HUD
подсказка «Пробел или клик — начать полёт», в сети — с обратным отсчётом; снимается при старте,
гибели, завершении раунда и сбросе мира.
